# ADR-001 — Backend Framework and Runtime

> **Project:** FoodWaste Intelligence (FWI)  
> **Status:** ACCEPTED FOR MVP WORKING BASELINE  
> **Decision ID:** ADR-001  
> **Scope:** P0/MVP prototype and production-oriented development baseline  
> **Date:** 2026-11-03  
> **Related:** FWI-PROD-001, FWI-ARCH-001, ADR-002

## 1. Context

FWI memerlukan backend web/API yang:

- menjaga domain logic terpisah dari framework;
- mendukung PostgreSQL sebagai canonical relational database;
- mendukung request/response validation;
- mendukung transactional application services;
- mudah diuji;
- dapat menghasilkan API contract yang jelas;
- cukup ringan untuk MVP namun mempunyai jalur pertumbuhan;
- mudah dipahami dan dipelihara oleh developer maupun AI coding agents;
- tidak memaksa asynchronous programming sebelum ada kebutuhan terukur.

FWI sudah memiliki domain Python awal di `src/fwi/domain/`. Keputusan backend tidak boleh memindahkan business rules inti ke route handler, ORM model, atau framework-specific object.

## 2. Decision

FWI menetapkan baseline backend:

- **Python 3.14.x**
- **FastAPI 0.146 line**
- **SQLAlchemy 2.1 line**
- **SQLAlchemy synchronous Session**
- **Alembic 1.20 line**
- **PostgreSQL 18.x** sesuai ADR-002
- **Pydantic** pada API/input-output boundary melalui ekosistem FastAPI

Patch/minor dependency yang tepat harus dikunci melalui dependency/lock mechanism pada implementation task. ADR ini mengunci arah teknologi, bukan setiap patch version selamanya.

## 3. Architectural Principle

Framework adalah delivery mechanism, bukan domain.

Dependency direction utama:

    API / FastAPI
          ↓
    Application layer
          ↓
       Domain

Infrastructure mengimplementasikan port/interface yang dibutuhkan application layer:

    Infrastructure / SQLAlchemy
              ↓
       Application ports

Domain tidak boleh mengimpor FastAPI, SQLAlchemy, Alembic, atau PostgreSQL driver.

## 4. Why FastAPI

FastAPI dipilih karena:

- API-first;
- menggunakan Python type hints;
- request/response validation terintegrasi;
- menghasilkan OpenAPI schema;
- dependency injection tersedia;
- testing HTTP relatif sederhana;
- tidak memaksa ORM tertentu;
- cocok dengan modular-monolith architecture FWI;
- memungkinkan domain Python yang sudah ada tetap independen.

FastAPI tidak menjadi tempat business rules utama.

Route handler seharusnya tipis dan bertanggung jawab terutama untuk:

1. menerima request;
2. validasi boundary;
3. memanggil application service/use case;
4. memetakan error;
5. menghasilkan response.

## 5. Why Python 3.14.x

Python 3.14 dipilih sebagai runtime baseline karena:

- masih berada pada active bugfix/support lifecycle;
- cukup modern untuk typing dan ecosystem saat ini;
- lebih konservatif daripada langsung menggunakan Python 3.15 yang baru dirilis;
- menyediakan runway support yang panjang untuk MVP.

Upgrade ke Python 3.15+ diperbolehkan melalui dependency/runtime review setelah compatibility test lulus.

## 6. SQLAlchemy Decision

FWI menggunakan **SQLAlchemy 2.1 ORM/Core ecosystem** untuk persistence implementation.

Namun:

- SQLAlchemy model bukan domain model;
- ORM object tidak boleh menjadi public API contract;
- repository/persistence mapping harus menjaga separation of concerns;
- query khusus reporting dapat menggunakan SQLAlchemy Core/SQL bila lebih tepat, tetapi tetap melalui infrastructure boundary.

## 7. Synchronous Database Access

FWI menetapkan **synchronous SQLAlchemy Session** sebagai baseline.

Alasan:

- lebih sederhana untuk MVP CRUD/audit-heavy workload;
- transaction reasoning lebih mudah;
- testing lebih sederhana;
- mengurangi complexity `async`/`await`, task context, dan session lifecycle;
- belum ada evidence bahwa database concurrency menjadi bottleneck.

Baseline tidak melarang async selamanya.

Perubahan ke AsyncSession memerlukan bukti seperti:

- load/profile test menunjukkan bottleneck;
- concurrency requirement yang nyata;
- external I/O parallelism dominan;
- long-lived/high-throughput connection requirement.

Perubahan tersebut harus direkam dalam ADR baru atau amendment.

## 8. FastAPI Endpoint Policy

Karena persistence baseline synchronous, endpoint yang melakukan blocking database I/O dapat menggunakan synchronous path operation (`def`) atau boundary yang memastikan blocking operation tidak dilakukan secara keliru pada event loop.

Jangan menambahkan `async def` hanya karena FastAPI mendukung async.

Jika endpoint menjadi async karena kebutuhan lain, blocking database operation harus tetap ditangani dengan pola yang aman dan eksplisit.

## 9. Alembic Migration Policy

Alembic digunakan untuk database schema migration.

Rules:

- semua schema change harus versioned;
- migration masuk Git;
- migration autogenerated wajib direview;
- destructive migration tidak boleh dijalankan tanpa review eksplisit;
- production schema tidak diubah manual sebagai workflow normal;
- migration harus selaras dengan PostgreSQL, bukan SQLite semantics;
- important constraints harus diuji.

Migration autogenerate adalah starting point, bukan sumber kebenaran otomatis.

## 10. Pydantic Boundary

Pydantic digunakan untuk:

- request schema;
- response schema;
- API-level parsing;
- serialization/deserialization;
- boundary validation yang bukan domain invariant.

Domain invariant tetap berada pada domain/application layer.

Contoh:

    JSON Request
         ↓
    Pydantic Schema
         ↓
    Application Command
         ↓
      Domain
         ↓
    Repository Port
         ↓
    SQLAlchemy Model
         ↓
     PostgreSQL

Tidak diperbolehkan melewatkan ORM entity langsung sebagai public API representation tanpa mapping yang disengaja.

## 11. Proposed Package Structure

Target baseline:

    src/fwi/
    ├── domain/
    │   ├── events.py
    │   ├── measurements.py
    │   └── validation.py
    │
    ├── application/
    │   ├── services/
    │   ├── ports/
    │   └── errors.py
    │
    ├── infrastructure/
    │   └── database/
    │       ├── models/
    │       ├── repositories/
    │       ├── mappings/
    │       └── session.py
    │
    └── api/
        ├── app.py
        ├── routes/
        ├── schemas/
        ├── dependencies/
        └── errors.py

Struktur dapat berevolusi, tetapi dependency direction tidak boleh dibalik.

## 12. Transaction Ownership

Transaction boundary dimiliki application/use-case layer, bukan domain entity dan bukan route handler secara implisit.

Contoh:

    BEGIN
      create material/waste event
      create required audit record
    COMMIT

Jika salah satu operasi gagal:

    ROLLBACK

Repository tidak boleh melakukan hidden commit yang membuat satu use case terpecah menjadi beberapa transaksi tanpa alasan eksplisit.

## 13. Session Lifecycle

Baseline:

- satu SQLAlchemy Session per request/use-case scope;
- session tidak disimpan secara global;
- session tidak dibagi lintas concurrent work;
- application service menerima repository/unit-of-work abstraction bila dibutuhkan;
- commit/rollback dilakukan pada transaction boundary yang jelas.

Detail Unit of Work implementation akan ditentukan saat persistence implementation task.

## 14. API Contract

FastAPI OpenAPI output digunakan sebagai technical API contract yang dapat diperiksa.

Namun OpenAPI bukan pengganti domain/product requirement.

API versioning policy detail belum dikunci oleh ADR ini.

P0 endpoint akan mengikuti P0 scope saja.

## 15. Testing Strategy

### Domain tests

Tetap dapat berjalan tanpa database.

### Application tests

Gunakan fake/stub repository jika sesuai untuk menguji use case.

### Integration tests

Gunakan PostgreSQL-compatible environment dan real SQLAlchemy mappings untuk:

- FK constraints;
- numeric precision;
- transaction rollback;
- uniqueness;
- event-to-measurement relationship;
- audit-related behavior.

### API tests

Gunakan FastAPI test client / HTTP tooling yang kompatibel untuk memverifikasi:

- request validation;
- status codes;
- response schema;
- error mapping;
- authorization boundary saat auth sudah diimplementasikan.

## 16. Dependency Management

Implementasi harus menggunakan reproducible dependency specification.

Rules:

- dependency version tidak dibiarkan sepenuhnya unbounded;
- exact resolved versions harus tercatat melalui lock strategy;
- upgrade dependency dilakukan sebagai task terpisah jika berisiko;
- security/bugfix updates boleh dipercepat tetapi tetap diuji;
- ADR tidak perlu diubah untuk setiap patch upgrade yang kompatibel.

Tool dependency manager/lockfile spesifik belum dikunci dalam ADR ini.

## 17. Alternatives Considered

### Django — NOT SELECTED

Django merupakan framework matang dengan ORM, migration, authentication, dan admin yang kuat.

Tidak dipilih sebagai baseline karena FWI ingin mempertahankan domain layer yang independen dan API-oriented architecture dengan framework footprint yang lebih kecil.

Keputusan ini bukan pernyataan bahwa Django tidak mampu memenuhi kebutuhan FWI.

### Flask — NOT SELECTED

Flask fleksibel dan ringan tetapi membutuhkan lebih banyak keputusan manual untuk validation, API contract, dependency conventions, dan project structure.

FWI ingin mengurangi architectural variance antar developer/AI agents.

### Async SQLAlchemy — DEFERRED

Didukung secara teknis tetapi tidak dipilih karena belum ada evidence kebutuhan concurrency yang membenarkan kompleksitas tambahan.

## 18. AI Agent Guardrails

AI coding agent tidak boleh:

- menaruh core domain rules di FastAPI route;
- mengganti sync SQLAlchemy menjadi AsyncSession tanpa keputusan;
- menggunakan ORM model sebagai domain entity secara diam-diam;
- membuat hidden commit di repository;
- membuat schema/table P1/P2 tanpa approved scope;
- mengganti PostgreSQL dengan SQLite sebagai canonical database;
- menambahkan framework/backend kedua tanpa ADR;
- meng-upgrade major dependency tanpa compatibility review;
- memasukkan secret/database credentials ke source control.

## 19. Acceptance Criteria

ADR-001 dianggap diterapkan ketika:

- [ ] Python runtime baseline didefinisikan;
- [ ] FastAPI application bootstrap tersedia;
- [ ] application/domain/infrastructure/API boundary terlihat pada package structure;
- [ ] SQLAlchemy synchronous engine/session tersedia;
- [ ] Alembic dikonfigurasi untuk PostgreSQL;
- [ ] dependency versions reproducible;
- [ ] minimal health endpoint tersedia;
- [ ] minimal database integration test tersedia;
- [ ] existing 11 domain tests tetap lulus;
- [ ] domain package tidak mengimpor FastAPI/SQLAlchemy;
- [ ] secret/database URL tidak masuk Git.
