## Implemented contract
- FR-002: append-only reference versions, explicit global principal/namespace grant independent of membership administration. Trusted `completion_seed.seed_authorities` requires an existing principal, registered namespace and approved source reference. No HTTP grant/delegation, self-registration, default administrator or invented vocabulary. Namespace row lock serializes expected-version append; stale version is409; version, actor audit and business write share the transaction. Ordinary authenticated reference reads remain available.
- FR-005 synthetic files: existing attachment metadata remains independent of file availability. POST/GET `/demo/v0.1/evidence/{UUID}/content` accepts PDF/JPEG/PNG signatures, at most10MiB; UUID filename, SHA-256, actor and metadata; actual event/measurement site authorization on both upload/read. `FWI_EVIDENCE_ROOT` must be an existing absolute private directory outside repository/public web root. POSIX rejects group/other access; Windows verifies real owner/DACL current principal/SYSTEM/Administrators only and fails503 if unverifiable. Deployers must also keep this root outside any independently served web root; application cannot discover all external servers. No public URL, inline preview, overwrite or deletion API. Writer uploads; reader downloads permitted site bytes only, with attachment/no-store/nosniff/CSP. Receiving a bounded body holds no authorization transaction; final transaction freshly checks session/CSRF/site after body completion.
- Storage is not a cross-filesystem/database distributed transaction. Known pre-commit audit failure removes only that operation's newly created file. Ambiguous COMMIT failure retains private bytes rather than risking deletion of referenced evidence; private orphan reconciliation is a remaining operational task. No automatic retention/deletion of referenced files. Signature check is not antivirus or full-document safety validation; synthetic files only. Production ADR-005 remains OPEN.
- FR-006: explicit reviewer grant per site independent of writer, no self-approval; prototype approval records version1/revision1, reason/actor/time and atomic audit. Duplicate/stale version or revision is409. Original event, measurement and proposal snapshots are immutable; proposal state remains `proposed` with separately derived approval status `approved_prototype`, `applied=false`. Numerical application, supersession/effective measurement selection and automatic KPI recalculation remain unavailable.
- AC-14: independent nullable regulatory/edibility fields and source provenance. Only source-supported `pending_assessment` regulatory status is accepted; no invented regulatory codes. Edibility is edible/inedible/mixed/unknown, separate from mass basis. Existing rows stay NULL; no classification backfill or safety inference. Capture/detail/export preserve source values.
- FR-008: existing CSV/JSON includes independent source classifications. XLSX/OD-006 remains OPEN; no dependency added.
- M4: receipt lists actual child lots, creates lots through existing parent API, reads stock and carries real lot identity into production; recipe/menu/batch and delivery/service identities are carried through existing UI. Child POSTs without a site field use existing backend parent authorization, not a fabricated field rejected by DTO. Per-target/sessionStorage UNKNOWN markers prevent replay; no GET unlock. No new generation event or effective-mass rule.
- M5: source-backed24 KPI catalogue metadata from FWI-03v1.3 (source SHA2565394dbcb7fd914a6635013cf7eb4eb7d2c293ffcab79561a10333b8176a6fa5a); no overwrite of existing catalogue history.
